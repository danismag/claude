## Найденные ошибки (было → стало)
- Лимиты inotify: «счётчик общий с вашими сессиями» → процессы узлов работают от root хоста и делят счётчик root (схема, пояснение, ответ на вопрос 1).
- «128 по умолчанию на многих Ubuntu» → 128 — значение ядра по умолчанию (inotify_user.c).
- Вывод `max_user_watches = 65536` выдуман → `…`. Добавлено: ядро считает лимит при загрузке от объёма памяти, от 8192 до 1048576.
- «Значения больше ваших — файл не нужен, уменьшать лимиты нельзя» → файл понизит лимит; впишите прежние значения или удалите файл.
- «512 безопасны на 8 ГБ» (без источника) → значения 512 и 524288 рекомендует документация kind (Known Issues).
- Уборка sysctl: объяснено, почему значения возвращаются только после перезагрузки (`sysctl --system` не сбрасывает удалённый параметр).
- «kind 0.32.0 создаёт узлы 1.36.1» → образ `kindest/node:v1.36.1` скрипт задаёт явно.
- Docker на Ubuntu: `docker.io` может быть ниже 27 → оговорка «иначе docker-ce из репозитория Docker».
- Таблица компонентов: реестр «02-2» → 02-1, 06-4; metrics-server «05-1, 05-4» → 05-4, 11-1; к kind добавлена 10-1. Убран код из ячеек.
- «Пороги eviction отключены» → уточнён механизм: kind задаёт дисковые пороги 0%, и kubelet обнуляет остальные, включая память (kind config.go, node-pressure-eviction.md).
- «Приложение пробует 60 с» → от 60 до 120 с: 30 попыток, пауза 2 с плюс connect_timeout 2 с; затем процесс завершается, и kubelet его перезапускает.

- crictl pull: «Image is up to date или Pulled» → crictl печатает `Image is up to date for` после любого успешного pull (cri-tools image.go).
- «Около 600 МиБ памяти подов» (не замер) → запросы 384 МиБ, пределы 1 ГиБ (по манифестам). «Около 200 МБ диска» → «до 1 ГБ (оценка)».
