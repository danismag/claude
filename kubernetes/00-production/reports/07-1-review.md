## Найденные ошибки (было → стало)

1. ЛР3, сценарий конфликта SSA. Писатель добавил шаг «перевести релиз на 2.1», чтобы `rollout undo` вернул 2.0, а потом Helm просил тот же 2.0. При одинаковом значении SSA не даёт конфликта: владение становится общим. Сценарий не воспроизвёл бы реальный вывод. → Восстановлен поток реального прогона: `rollout undo` уводит на ReplicaSet `2.9` из ЛР2, Helm ставит 2.0, конфликт есть. Шаг 1 удалён, шаги перенумерованы 1–5, «Итог», «Риски» и «Что понадобится» исправлены.
2. ЛР2 шаг 4: вывод `4 … deployed … Rollback to 1` не сходится с порядком шагов. По коду `failRelease` (pkg/action/upgrade.go v4.2.2) откат идёт на последнюю ревизию в статусе deployed/superseded, то есть на ревизию 3. → Ожидаемый обобщённый вывод: строка `failed` с `Upgrade "shop" failed`, строка `deployed` с `Rollback to …`. В разбор добавлено правило выбора ревизии.
3. §3 `--server-side`: «значение `auto` по умолчанию» для всех команд → у `install` флаг логический, по умолчанию `true`; у `upgrade` и `rollback` значения `true/false/auto`, по умолчанию `auto` (cmd/install.go, upgrade.go, rollback.go v4.2.2).
4. §1: «`--atomic` переименован» без статуса старого имени → `--atomic` и `--force` остаются как устаревшие алиасы и печатают предупреждение (`MarkDeprecated("atomic", "use --rollback-on-failure instead")`). Это записано как анти-рецепт.
5. §3 «Таймаут должен превышать progressDeadlineSeconds… хватает 2–5 минут» — рекомендация придумана и логически спутана → 5 мин по умолчанию меньше 600 с, поэтому Helm объявит failed раньше Deployment; тайм-аут выбирают по длительности выкатки, а job в CI делают длиннее.
6. §2 хранение: «сжатый JSON» → ключ `release`, gzip + base64 от Helm, плюс base64 самого Secret: при ручном чтении декодируют дважды (driver/secrets.go: «base64 encoded gzipped string»).
7. §5 hooks: «в аннотации нет before-hook-creation» — при отсутствии аннотации эта политика и так по умолчанию → «политика задана без before-hook-creation… Job с постоянным именем». Ответ на вопрос 2 ЛР4 уточнён так же: у Job лабы имя с номером ревизии.
8. §6 «Имя релиза: строчные буквы, цифры и дефис» → допускается и точка, начало и конец — буква или цифра, до 53 символов.
9. §5 и §3 конфликт: «ручная правка → upgrade падает» → только если upgrade задаёт тем же полям другое значение.
10. ЛР4 «Риски»: «postgres:17.6-alpine около 100 МБ» — число придумано → тот же образ, что у базы стенда; узел без него скачает его.
11. §1 добавлены (research-k8s-changes): `--wait=legacy`; OCI — `helm registry login` только с доменом и установка по дайджесту (helm-www docs/overview.md); метод релизов Helm 3 при upgrade из Helm 4 — client-side; текущая линия 4.3 (4.3.1 от 2026-10-15).
12. §6: раздел из 2 подразделов → 3 («Значения по умолчанию», «Ограничения хранения», «Ограничения поведения»). Добавлен факт: hooks не входят в релиз, `uninstall` их не удаляет (charts_hooks.md).
13. Строки кода > 100 знаков (8 шт.): NOTES.txt разбит на две строки; `jq` и `psql` перенесены `\`. Строки вывода сокращены или перенесены с пометкой «длинная строка перенесена». В выводе install добавлено `…` вместо пропущенной LAST DEPLOYED. Аббревиатура SSA расшифрована при первом упоминании.

## Подтверждено (источник)

- `--server-side` (install bool true; upgrade/rollback auto), `--force-conflicts`, `--rollback-on-failure` (включает watcher при hookOnly), `--atomic`/`--force` как устаревшие алиасы, `--force-replace`, `--timeout` 300 с, `--wait-for-jobs`, `--reset-then-reuse-values`, `--history-max` — github.com/helm/helm v4.2.2 pkg/cmd/{install,upgrade,rollback}.go.
- `--wait`: без флага `hookOnly`, без значения `watcher`, есть `legacy` — pkg/cmd/flags.go v4.2.2.
- Отказ upgrade при pending (errPending), выбор ревизии отката, текст «has been rolled back due to rollback-on-failure being set», описание «Preparing upgrade» — pkg/action/upgrade.go v4.2.2.
- Rollback без номера → предыдущая ревизия — pkg/cmd/rollback.go.
- Secret: тип `helm.sh/release.v1`, метки owner/name/status/version/modifiedAt, gzip+base64 — pkg/storage/driver/secrets.go.
- Hooks: 9 типов включая test, политика по умолчанию before-hook-creation, сортировка по весу по возрастанию, ожидание Job/Pod, вне релиза — helm-www docs/topics/charts_hooks.md.
- Helm 4: SSA для новых релизов, upgrade/rollback следуют прошлому методу, переименования флагов с предупреждением, post-renderer только плагином, Wasm опционально, OCI по дайджесту, registry login только домен — helm-www docs/overview.md; дата 12 ноября (страница релиза v4.0.0).
- Helm 3: исправления до финального релиза 2026-09-09, безопасность до 2027-02-10 — blog.helm.sh/blog/helm-v3-end-of-life (через поиск).
- Существование 4.2.2 (между 4.2.0 и 4.2.3), 4.3.0/4.3.1 — github.com/helm/helm/releases.
- Реальный вывод (lint, required, install, Secret, managedFields, `Updated: 1/2`, конфликт с "kubectl", exit=137/pending-upgrade/another operation, Rollback was a success, хэши 3a12bfdf1e09 → b300b04a65b2, schema_version 8, discount 10) — старая версия части.
