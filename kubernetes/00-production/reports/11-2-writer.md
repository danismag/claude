## 4. Что выкинуто или переносится (для 12-2 и 12-1)

Из 10 тренажёров в части оставлены 4 класса (Pending по ресурсам/taint, образ, StartError, Running не Ready), остальные шесть и суть остальных материалов переносятся:

- t02 (реестр недоступен): `failed to do request: Head "https://registry.invalid.lab/v2/app/manifests/1.0…` — ошибка до реестра, а не «не найдено». Остался одной строкой в §5.
- t03 (приложение падает): `python -c` печатает `db config missing` и выходит с 1; `Error` / `CrashLoopBackOff`, `lastState: Error/1`; `kubectl logs` в back-off показывает последний экземпляр, `--previous` на стенде отвечал `unable to retrieve container logs`.
- t04 (нет ConfigMap): `envFrom` на `app-config` → `CreateContainerConfigError`, `configmap "app-config" not found`; под оживает после создания ConfigMap без пересоздания, но не мгновенно (через 6 с ещё ошибка).
- t05 (OOM): python выделяет 300 МиБ при лимите 128Mi → `OOMKilled/137`, событий про OOM нет, смотреть Last State и журнал ядра.
- t07 (селектор): `nodeSelector: disktype=nvme`, метки нет → `3 node(s) didn't match Pod's node affinity/selector`.
- t08 (PVC): PVC с `storageClassName: fast-ssd`, класса нет → у пода `pod has unbound immediate PersistentVolumeClaims`, у PVC `storageclass.storage.k8s.io "fast-ssd" not found`; причина в событиях PVC.
- Сводка `get pods` через 50 с: t01 ImagePullBackOff 0, t02 ImagePullBackOff 0, t03 Error 3, t04 CreateContainerConfigError 0, t05 OOMKilled 2, t06/t07/t08 Pending 0, t09 Running 0/1, t10 RunContainerError 3. Быстрое исправление: тег 2.0, request 100m, без nodeSelector, StorageClass standard, проба /ready, лимит 512Mi.
- Кейс из прода «Pending два часа — а дело в зоне диска»: StatefulSet из 3 реплик, одна Pending; `FailedScheduling: 0/12 nodes are available: 4 Insufficient memory, 8 node(s) had volume node affinity conflict`; PVC в зоне b, узлы автоскейлер добавил в зонах a и c; лечение — ёмкость в зоне диска, topology spread, читать сообщение целиком.
- Вопросы с собеседования (6): CrashLoopBackOff, ImagePullBackOff, Pending, Running но не Ready, приложение или платформа, падение без логов и без shell (термин-сообщение, `--copy-to`, образ-отладчик с `--share-processes`, журнал ядра, `crictl inspect`).
- Подводные камни: `--previous` недоступен в момент перезапуска; OOM без событий; ошибки PVC в событиях PVC; CreateContainerConfigError чинится созданием объекта; `nodeName` в манифесте прячет ошибки scheduler; ошибки admission и квот — в событиях ReplicaSet/Job; читать FailedScheduling целиком.
