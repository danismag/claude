## Находки, требующие решения

1. 10-3 (вступление к лабораторным): «версию задаёт переменная NODE_IMAGE». В lab-up.sh это константа (`NODE_IMAGE=kindest/node:v1.36.1`), окружением она не переопределяется. В C.10 написано «правьте эту строку». Нужно поправить формулировку 10-3 или сделать `NODE_IMAGE=${NODE_IMAGE:-…}` в скрипте.
2. 01-1 §4 (карточка etcdctl) советует в Ubuntu пакет etcd-client. В Ubuntu 24.04 это etcdctl 3.4.30, без etcdutl, при кластере на etcd 3.6. В B.2 добавлен подраздел-предупреждение; в 01-1 стоит добавить фразу о версии.
3. В lab-up.sh комментарий «registry:2», а переменная REG_IMAGE=registry:2.8.3 (мелочь).
4. 03-2 §6 указывает ClusterIP 10.96.0.0/16, старое приложение C — 10.96.0.0/12; в C взято значение из 03-2, в lab-up.sh диапазон не задан.

## Сомнительные места

1. Ядро Ubuntu 24.04 «6.8» — из памяти, не из частей и не проверено.
2. Пакеты Manjaro crictl, cosign, etcd, jq названы по карточкам частей; версии не снимались. Docker 29.7.2 и остальные версии Manjaro — из старой версии B.
3. Имена файлов сумм (таблица B.3) взяты из текста частей; для krew в части написано «файл .sha256 рядом с архивом», точное имя не приведено. Для kind, helm, etcd, kustomize имена не даны намеренно.
4. «Ubuntu: 128 экземпляров inotify по умолчанию» — формулировка 00-1; на Ubuntu 24.04 не измерялась. Указано в B.6.
5. Ресурсы: для cert-manager, KEDA, kube-state-metrics, cosign, lab-06-4 чисел в частях нет, в C.7 это сказано явно. «До 5 ГиБ» для Argo CD и Gitea — ориентир плана без замера.
6. C.8 повторяет команды из «Уборки» частей (в CNPG функция `k` заменена на `kubectl -n lab-09-1`). При правке частей блоки надо синхронизировать.
7. Список «где используются общие образы» в C.3 дан на уровне модулей по grep имён образов, не по всем частям.
8. Возврат стенда на 1.36.1 (C.10) — цепочка cp, purge, up, пересборка; целиком не проходилась. Команда `cp -a ~/lab/k8s ~/lab-k8s-backup` добавлена писателем, в частях её нет.
9. Блок удаления cert-manager в C.8 начинается с возврата Gateway `lab` (команды из 03-5, работа 1); если работа 1 прошла штатно, патч вернёт ошибку `remove` по несуществующему пути — это безопасно, но стоит учесть.
10. Лимит свободного места 20 ГБ взят из 00-1 (работа 1, шаг 1); старое приложение называло 15 ГБ.
