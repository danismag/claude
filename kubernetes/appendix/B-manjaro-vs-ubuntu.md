# Приложение B. Manjaro и Ubuntu

Назначение: найти, чем отличается установка инструментов курса и настройка хоста в Ubuntu 24.04 и в Manjaro, и какие из этих сведений не проверены.

## Как пользоваться

Стенд работает в контейнерах Docker (kind), поэтому от дистрибутива зависят только две вещи: клиентские программы на хосте и настройки ядра хоста. Узлы кластера, kubelet и containerd одинаковы везде.

Курс даёт команды в форме Ubuntu. Здесь собраны отличия Manjaro и случаи, когда в Ubuntu нет пакета. Разделы идут в порядке установки. Сначала Docker (B.1) и клиенты (B.2), затем проверка суммы (B.3), хост и ядро (B.4), обновления (B.5) и непроверенное (B.6).

Версии пакетов Ubuntu сняты со страниц packages.ubuntu.com 19 октября 2026 года, версии Manjaro — командой `pacman -Si` на машине автора в октябре 2026 года. Установка на Ubuntu в курсе не выполнялась, подробности в B.6.

## B.1. Docker

Docker запускает узлы kind и реестр стенда, поэтому его ставят первым. Курс требует Docker 27 или новее (00-1, работа 1, шаг 2).

- **Ubuntu 24.04.** Пакет `docker.io`: в выпуске 24.0.7, в обновлениях `noble-updates` — 29.1.3. Версию покажет `apt-cache policy docker.io`. Если она ниже 27, берите `docker-ce` из репозитория Docker.
- **Manjaro.** Пакет `docker` (29.7.2 на машине автора). Службу включают вручную: `sudo systemctl enable --now docker`.
- **Обе системы.** Команда `sudo usermod -aG docker "$USER"` и новый вход в сеанс. Группа `docker` даёт права, равные root на хосте.

Если `docker pull` отвечает `error getting credentials`, в `~/.docker/config.json` остался ключ `credsStore` от Docker Desktop. Запускайте команды стенда с `DOCKER_CONFIG=$(mktemp -d)` или удалите ключ (00-1 §5).

### Что стоит знать о таблицах

Замечания к обеим таблицам:

- **kind, kubectl, helm, kustomize, k9s, stern.** В Ubuntu 24.04 стандартных пакетов для них нет. Для kubectl и cri-tools добавляют репозиторий `pkgs.k8s.io` (00-1, работа 1, шаг 3).
- **kubectx.** В Ubuntu 24.04 есть пакет `kubectx` версии 0.9.5, а курс использует 0.11.0 из релиза (00-2, работа 1, шаг 9).
- **Helm 4 и kustomize.** В Helm 4 флаг `--rollback-on-failure` заменил `--atomic`, а server-side apply включён по умолчанию (07-1). В курсе хватает `kubectl kustomize`; отдельный бинарник нужен для `kustomize edit` (07-3 §3).
- **argocd.** Версия клиента должна совпадать с версией сервера, 3.5.5 (08-1 §3). Пакет Manjaro на машине автора был 3.4.2, поэтому сверяйте `argocd version --client`.
- **cosign.** Лабораторная работа 3 из 06-4 использует бинарник v2.5.3 из релиза в обеих системах, чтобы версия не менялась.
- **velero.** Клиент v1.18.4 берут из релиза и кладут в `~/lab/k8s/04-3/bin` (04-3, работа 3, шаг 1).
- **crictl и etcdctl.** На хост они не нужны: обе программы есть внутри узлов kind и пода etcd (A.3, A.5).

### Ловушка: etcd-client в Ubuntu

Пакет `etcd-client` в Ubuntu 24.04 содержит etcdctl 3.4.30, а кластер стенда работает на etcd 3.6. В версии 3.4 нет `etcdutl`, а в 3.6 команды `snapshot status` и `snapshot restore` доступны только в нём (10-2 §3). Карточка в 01-1 §4 называет пакет `etcd-client` для простых запросов. Для работы со снимками берите архив релиза etcd 3.6: в нём лежат оба файла.

## B.3. Бинарник с релиза с проверкой суммы

Бинарник из интернета запускается с вашими правами, поэтому перед установкой сверьте его сумму SHA-256 с файлом, который проект публикует на странице релиза. Схема одинакова для всех инструментов.

```bash
V=v1.2.3                                   # закреплённая версия
U=https://github.com/ORG/REPO/releases/download/$V
D=$(mktemp -d) && cd "$D"
curl -fsSLO "$U/ФАЙЛ.tar.gz"               # архив или бинарник
curl -fsSLO "$U/ФАЙЛ_СУММ"                 # файл сумм релиза
sha256sum --ignore-missing -c ФАЙЛ_СУММ    # ждём строку «…: OK»
```

Команда `sha256sum -c` читает файл сумм и считает суммы файлов из текущего каталога. Ключ `--ignore-missing` пропускает записи о файлах, которых вы не скачивали. Если строки `OK` нет или она заменена на `FAILED`, не устанавливайте файл: скачайте заново или сверьте версию.

Таблица показывает, как называется файл сумм у инструментов, где курс сверяет сумму.

| Инструмент | Файл сумм | Где в курсе |
|---|---|---|
| argocd | cli_checksums.txt | 08-1 §3 |
| velero | CHECKSUM | 04-3, работа 3 |
| cosign | cosign_checksums.txt | 06-4, работа 3 |
| kubectx | checksums.txt | 00-2, работа 1 |
| stern | checksums.txt | 00-2, работа 3 |
| k9s | checksums.sha256 | 00-2, работа 3 |
| krew | .sha256 рядом с архивом | 00-2, работа 1 |

Разбор: для cosign файл сумм содержит строки для разных платформ, поэтому курс сначала выбирает свою строку командой `grep ' cosign-linux-amd64$' cosign_checksums.txt | sha256sum -c -`. Для kind, helm, etcd и kustomize курс не показывает проверку суммы. Имя файла сумм у них смотрите на странице релиза проекта.

После проверки файл кладут в `PATH` командой `sudo install -m 0755 файл /usr/local/bin/имя`. Права 0755 разрешают всем запуск и запрещают запись.

## B.4. Хост и ядро

Хост задаёт четыре вещи: лимиты inotify, версию cgroup, модуль безопасности ядра и версию ядра. Все четыре проверяются командами только на чтение.

### Лимиты inotify

**inotify** — механизм ядра, который сообщает программам об изменениях файлов. Каждый узел kind запускает systemd и kubelet, а они занимают экземпляры inotify. Лимит считается на пользователя, и все узлы стенда делят его (00-1, работа 1, шаг 4).

```bash
sysctl fs.inotify.max_user_instances fs.inotify.max_user_watches
```

Команда печатает два лимита. Ubuntu по умолчанию даёт 128 экземпляров, и четыре узла с этим лимитом падают с ошибкой `too many open files`. На машине автора в Manjaro стояло 1024, ошибок не было.

Курс поднимает лимиты до значений из документации kind: 512 экземпляров и 524288 наблюдений.

```bash
sudo tee /etc/sysctl.d/99-kind.conf <<'EOF'
fs.inotify.max_user_instances = 512
fs.inotify.max_user_watches = 524288
EOF
sudo sysctl --system
```

Файл переживает перезагрузку. Если в системе значение уже выше, файл его понизит: в этом случае впишите прежнее число. Кластер `lab-10-1` добавляет ещё четыре узла (10-1), и лимит 512 рассчитан и на них.

### Версия cgroup

**cgroup v2** — вторая версия механизма ядра, который ограничивает ресурсы процессов. Kubelet 1.35 и новее не запускается на cgroup v1 (01-2 §6).

```bash
stat -fc %T /sys/fs/cgroup/
```

Ответ `cgroup2fs` значит, что хост на cgroup v2; ответ `tmpfs` значит cgroup v1. Ubuntu использует v2 с версии 21.10, Manjaro — по умолчанию. Узлы kind используют cgroup хоста, поэтому проверка нужна только на хосте.

### AppArmor и SELinux

**AppArmor** и **SELinux** — модули безопасности ядра, которые ограничивают доступ процесса к файлам и объектам ядра. На хосте обычно включён один из них (06-2 §2).

- **Ubuntu.** AppArmor включён по умолчанию.
- **Manjaro.** Ни AppArmor, ни SELinux по умолчанию не включены.
- **SELinux.** Используется в дистрибутивах семейства RHEL. Ни Ubuntu, ни Manjaro его не включают, поэтому тома курса (04-2) не требуют меток.

Узлы kind делят ядро с хостом, но containerd внутри узла AppArmor не применяет: в образе узла нет `apparmor_parser`. Под с явным полем `appArmorProfile` на стенде не запустится в обеих системах (06-2, работа 2).

```bash
docker exec lab-worker cat /sys/module/apparmor/parameters/enabled
```

Ответ `Y` значит, что модуль включён в ядре хоста (типично для Ubuntu), `N` — что он собран, но выключен (типично для Manjaro). Если файла нет, ядро собрано без AppArmor.

### Версия ядра

Узлы kind работают на ядре хоста, поэтому возможности стенда зависят от `uname -r`. Таблица показывает минимальные версии, на которые опираются части курса.

| Возможность | Ядро | Часть |
|---|---|---|
| cgroup v2 | 5.8 | 01-2 §6 |
| Memory QoS | 5.9 | 05-1 §6 |
| PSI (`CONFIG_PSI=y`) | 4.20 | 05-1 §4 |
| Режим nftables в kube-proxy | 5.13 | 03-2 §1 |
| User namespaces подов | 6.3 | 06-2, работа 3 |

Ubuntu 24.04 поставляется с ядром 6.8. В Manjaro ядро выбирают из установленных: список покажет `mhwd-kernel -li`, текущее — `uname -r`. Версии ядра машины автора в плане не записаны, поэтому работа 3 из 06-2 помечена как непроверенная.

### Прочие отличия хоста

- **Имена `*.localhost`.** Systemd-resolved в Ubuntu сопоставляет их с 127.0.0.1. На машине автора в Manjaro `getent hosts orders.localhost` вернул `::1`, и если Envoy слушает только IPv4, используйте `curl -4` или `127.0.0.1` с заголовком `-H Host:`.
- **Порт 8088.** Стенд занимает его вместо 8080, потому что на машине автора 8080 был занят.
- **Диск.** Под `/var/lib/docker` нужно не меньше 20 ГБ свободно (00-1, работа 1, шаг 1). Kind отключает пороги eviction, поэтому DiskPressure на стенде не воспроизводится (00-1 §6, 01-2 §6).
- **Автодополнение bash.** В Ubuntu ставят `bash-completion` и пишут вывод `kubectl completion bash` в `/etc/bash_completion.d/kubectl`. В Manjaro пакеты kubectl и helm кладут файлы дополнения сами.

## B.5. Обновления

Дистрибутивы по-разному относятся к версиям, а курс закрепляет Kubernetes 1.36.

- **Manjaro** обновляется по схеме rolling: `pacman -Syu` может поднять kubectl на минорную версию. Версия kubectl 1.37 с кластером 1.36 допустима (разница в одну минорную версию), но флаги Helm 4.3 и новее сверяйте с документацией. Чтобы закрепить версии на время курса, добавьте в `/etc/pacman.conf` строку `IgnorePkg = kubectl helm`.
- **Ubuntu** привязывает репозиторий `pkgs.k8s.io` к минорной версии: адрес содержит `v1.36`. Для перехода на 1.37 замените адрес в `/etc/apt/sources.list.d/kubernetes.list`. Чтобы обычное обновление не сменило версию, выполните `sudo apt-mark hold kubectl` (10-3 §3).
- **Helm и другие бинарники из релизов** сами не обновляются. Новую версию ставят тем же способом (B.3).

## B.6. Что не проверено

Курс написан в режиме «только текст»: команды установки не запускались. Проверка по частям записана в таблице 00-plan §7.

- **Ubuntu 24.04.** Установка Docker, kind, kubectl, helm, kubectx, krew, stern, k9s, crictl не выполнялась (00-plan §7, строки 00-1 и 00-2). Проверены только версии и наличие пакетов на сайте packages.ubuntu.com.
- **Manjaro.** Версии kind, kubectl, helm, kustomize, k9s, stern, kubectx, krew, argocd, docker взяты из `pacman -Si` на машине автора. Пакеты `crictl`, `cosign`, `etcd`, `jq` названы в карточках частей, но версии не снимались; в плане § 7 пакеты crictl, krew, kubectx, stern и k9s отмечены как непроверенные.
- **Файлы сумм.** Имена файлов сумм для kind, helm, etcd и kustomize не проверялись.
- **inotify.** Значение 128 для Ubuntu взято из документации kind и из текста 00-1; на реальной Ubuntu 24.04 оно не снималось.
- **AppArmor.** Ответы `Y` и `N` для Ubuntu и Manjaro типичны, а не измерены (00-plan §7, строка 06-2).
