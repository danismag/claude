# Приложение D. Глоссарий RU/EN

Назначение: найти за секунду, что означает термин курса, как он звучит по-английски и в какой части разобран.

## Как пользоваться

Термины идут по алфавиту: сначала русские, затем английские названия объектов и инструментов. В конце записи стоит часть, где термин впервые определён. Если у термина есть русское и английское название, запись стоит под обоими. Слова, которые на собеседовании называют только по-английски (Deployment, Service, Pod), даны без перевода в скобках.

Четыре места легко спутать:

- **Выселение** (eviction, 05-5) — завершение пода по решению компонента кластера: Eviction API или kubelet при нехватке ресурсов узла.
- **Вытеснение** (preemption, 05-3) — удаление менее важных подов, чтобы scheduler поставил более важный. Вытеснение kubelet'ом по давлению (05-5) — это eviction, а не preemption.
- **Песочница пода** (pod sandbox, 01-2) — контейнер pause, который держит сеть пода. **Песочница рантайма** (runtime sandbox, 06-2) — отдельное ядро или ВМ для недоверенного кода.
- **ServiceAccount** (06-1) — учётная запись процессов в подах; в 04-1 и 05-2 он упоминается, но определён в 06-1.
- **Хуки.** Хук Helm (07-1) работает при установке релиза, хук Argo CD (08-1) работает на фазе sync; волны Argo CD (08-1) только упорядочивают объекты.

## А

- **Авторизатор** (authorizer) — модуль API-сервера, который отвечает на действие «разрешить», «запретить» или «нет мнения» (06-1).
- **Авторизация** (authorization) — проверка, что аутентифицированному субъекту разрешено действие; отказ даёт 403 (01-1).
- **Агрегированная ClusterRole** (aggregated ClusterRole) — роль с полем aggregationRule, правила которой контроллер собирает из других ClusterRole по меткам (06-1).
- **Аддитивность** (additive) — свойство NetworkPolicy: политики только разрешают трафик и никогда не запрещают (03-6).
- **Аддон** (add-on) — компонент поверх ядра кластера, например CoreDNS, metrics-server или CSI-драйвер (01-1).
- **Адресат токена** (audience, claim aud) — поле JWT, которое называет службу, для которой выпущен токен (06-1).
- **Аннотация** (annotation) — пара «ключ=значение» на объекте для произвольных данных, по которой объекты не выбирают (01-3).
- **Аудит** (audit) — запись каждого запроса к API-серверу: кто прислал, к какому объекту, какой командой и с каким итогом (06-4).
- **Аутентификация** (authentication) — шаг, на котором API-сервер узнаёт, кто пришёл: по сертификату, токену или OIDC; провал даёт 401 (01-1).

## Б

- **Балансировщик нагрузки** (load balancer) — процесс или устройство, которое принимает соединения на одном адресе и раздаёт их узлам или подам (10-1).
- **Блокировка задержки** (delay inhibitor lock) — блокировка systemd, которая даёт kubelet время остановить поды при выключении узла (05-5).
- **Бэкап** (backup) — копия данных, из которой их можно восстановить после потери оригинала (04-3).
- **Бэкенд etcd** (etcd backend) — основная база etcd, файл member/snap/db в каталоге данных (10-2).
- **Бэкенд аудита** (audit backend) — место, куда API-сервер отправляет события аудита: файл или вебхук (06-4).
- **Бюджет прерываний** (PodDisruptionBudget, PDB) — объект, который задаёт, сколько подов набора должны оставаться доступными при добровольных прерываниях (05-5).

## В

- **Вебхук допуска** (admission webhook) — HTTPS-сервис, который API-сервер вызывает при admission: он разрешает, запрещает или меняет объект (09-2).
- **Вебхук токенов** (token webhook) — внешняя служба, которой API-сервер отправляет токен запросом TokenReview для аутентификации (06-1).
- **Вес CPU** (cpu.weight) — число cgroup от 1 до 10000 (по умолчанию 100), по которому ядро делит процессор при нехватке (05-1).
- **Взаимный TLS** (mTLS, mutual TLS) — проверка сертификатов в обе стороны: клиент проверяет сервер, а сервер клиента (01-1).
- **Волна синхронизации** (sync wave) — аннотация Argo CD с целым числом (по умолчанию 0): объекты с меньшим числом применяются раньше (08-1).
- **Выбор лидера** (leader election) — способ договориться, какая из копий программы главная; копии борются за один объект Lease (01-1).
- **Выкатка** (rollout) — замена старых подов Deployment новыми (02-2).
- **Выселение** (eviction) — завершение пода по решению компонента кластера, а не его владельца: через Eviction API или kubelet (05-5).
- **Вытеснение** (preemption) — удаление подов с меньшим приоритетом, чтобы освободить место для более важного пода (05-3).
- **Вытеснение по давлению** (node-pressure eviction) — выселение подов kubelet'ом, когда ресурсов узла остаётся меньше порога; это eviction, а не preemption (05-5).

## Г

- **Гистограмма** (histogram) — тип метрики: набор счётчиков по корзинам, из которых считают процентили задержки (11-1).
- **Глагол** (verb) — действие над объектом в RBAC: get, list, watch, create, update, patch, delete (06-1).

## Д

- **Дайджест** (digest) — хэш содержимого образа вида sha256:…, который однозначно называет образ (00-1).
- **Дамп** (dump) — результат логического бэкапа базы; для PostgreSQL его делает pg_dump (04-3).
- **Дерево решений** (decision tree) — последовательность вопросов, каждый из которых отсекает половину возможных причин (11-2).
- **Дефрагментация etcd** (defragmentation) — перестройка файла базы etcd, которая возвращает свободные страницы системе (10-2).
- **Добровольное прерывание** (voluntary disruption) — уход пода с узла по воле человека или контроллера: drain, обновление группы узлов (05-5).
- **Домен топологии** (topology domain) — группа узлов с одним значением метки topologyKey (05-3).
- **Доступный под** (available) — под в состоянии Ready, который остаётся таким не меньше minReadySeconds (по умолчанию 0) (02-2).
- **Драйвер cgroups** (cgroup driver) — то, что создаёт группы cgroup: сам kubelet (cgroupfs) или systemd (01-2).
- **Дрейф** (drift) — расхождение между состоянием в Git и живым состоянием в кластере (08-1).

## Ж

- **Желаемое состояние** (desired state) — то, что должно быть: поле spec объекта или манифесты в Git (01-1).
- **Жёсткий порог** (evictionHard) — порог выселения, при котором kubelet выселяет под сразу, с нулевым grace period (05-5).
- **Живое состояние** (live state) — объекты, которые существуют в кластере сейчас (08-1).
- **Журнал systemd** (journal) — хранилище логов systemd, которое читают командой journalctl (00-2).

## З

- **Завершение TLS** (TLS termination) — режим, в котором Gateway расшифровывает запрос и читает заголовки и пути (03-5).
- **Заказ ACME** (Order) — объект cert-manager с перечнем имён, на которые запрошен сертификат (03-5).
- **Значения** (values) — параметры, которые Helm подставляет в шаблоны чарта (07-1).
- **Зонтичный чарт** (umbrella chart) — чарт-родитель, который собирает несколько субчартов в один релиз (07-2).

## И

- **Идентичность** (identity) — набор свойств экземпляра StatefulSet: имя, сетевой адрес и данные на диске (02-3).
- **Измеритель** (gauge) — тип метрики: текущее значение, которое растёт и падает (11-1).
- **Изолированный под** (isolated) — под, который выбрала хотя бы одна NetworkPolicy данного направления: разрешён только указанный трафик (03-6).
- **Инкапсуляция** (encapsulation) — упаковка пакета пода внутрь пакета между узлами в оверлейной сети (03-1).
- **Исключение PSA** (exemption) — запрос, который Pod Security Admission не проверяет вообще (06-3).

## К

- **Канал обновлений** (release channel) — настройка управляемого кластера, которая решает, как быстро он получает новые версии (10-3).
- **Канарейка** (canary) — приём, при котором новую версию сначала получает малая доля трафика (02-2).
- **Кворум** (quorum) — большинство членов etcd (N/2 вниз плюс 1), нужное для записи (01-1).
- **Квота** (ResourceQuota) — объект namespace, который ограничивает сумму ресурсов и число объектов в нём (05-2).
- **Класс QoS** (QoS class) — категория пода по requests и limits: Guaranteed, Burstable или BestEffort (01-2).
- **Код выхода** (exit code) — число, с которым завершился процесс; по нему видно, кто и как его остановил (02-1).
- **Компакция** (compaction) — удаление старых ревизий etcd до заданной, при котором остаётся последнее значение каждого ключа (01-1).
- **Конвертация CRD** (conversion) — преобразование объекта CRD между версиями API (09-1).
- **Контейнер** (container) — процесс с собственной файловой системой и ограничениями ядра (02-1).
- **Контейнерный рантайм** (container runtime) — служба, которая хранит образы и запускает контейнеры, например containerd (01-2).
- **Контекст** (context) — именованная связка «кластер, пользователь, namespace по умолчанию» в kubeconfig (00-2).
- **Контроллер** (controller) — программа, которая следит за объектами одного вида и приводит факт к желаемому (01-1).
- **Конфликт** (conflict) — ответ сервера, если менеджер пишет в поле, которым владеет другой менеджер (01-3).
- **Корневой CA** (root CA) — самоподписанный сертификат, заранее известный клиенту (03-5).

## Л

- **Лидер etcd** (leader) — член etcd, который принимает все записи и рассылает их остальным (10-2).
- **Листовой сертификат** (leaf certificate) — сертификат компонента, подписанный центром сертификации (10-4).
- **Логи** (logs) — текст, который пишут процессы: контейнеры, kubelet, компоненты control plane (11-1).
- **Логический бэкап** (logical backup) — выгрузка содержимого базы в виде команд или записей, а не файлов диска (04-3).

## М

- **Менеджер поля** (field manager) — имя клиента, который записал поле объекта; основа server-side apply (01-1).
- **Метка** (label) — пара «ключ=значение» на объекте, по которой объекты выбирают (01-3).
- **Метрика** (metric) — именованное число с метками, например apiserver_request_total (11-1).
- **Метрики** (metrics) — числа во времени: загрузка CPU пода, число запросов к API-серверу (11-1).
- **Милликор** (millicore) — одна тысячная ядра CPU, суффикс m: 250m равно четверти ядра (05-1).
- **Мультитенантность** (multi-tenancy) — работа нескольких команд или клиентов (арендаторов) в одном кластере (06-1).
- **Мягкий порог** (evictionSoft) — порог выселения, который действует, если сигнал ниже порога дольше заданного срока (05-5).

## Н

- **Нативный sidecar** (native sidecar) — init-контейнер с restartPolicy: Always, который работает рядом с основными (02-1).
- **Недобровольное прерывание** (involuntary disruption) — уход пода, который произошёл сам: отказ железа, паника ядра, потеря узла из сети (05-5).

## О

- **Объект** (object) — запись в API, которая описывает, что должно быть в кластере и что там есть (01-3).
- **Оверлей** (overlay) — способ сети подов, при котором пакет пода кладут внутрь пакета между узлами (03-1).
- **Окно обслуживания** (maintenance window) — интервал, в который облако вправе обновлять управляемый кластер (10-3).
- **Окно стабилизации** (stabilization window) — время, за которое HPA запоминает прошлые рекомендации, чтобы не колебаться (05-4).
- **Оператор** (operator) — CRD вместе с контроллером, который знает предметную область: как развернуть БД, сделать бэкап, переключить роль (09-1).
- **Оптимистичная конкуренция** (optimistic concurrency) — запись без блокировок: первый выигрывает, остальные перечитывают объект и повторяют (01-1).
- **Отсечение полей** (pruning) — удаление API-сервером при записи полей, которых нет в схеме CRD (09-1).
- **Очередь отсрочки** (backoff queue) — очередь scheduler: поды ждут перед повторной попыткой от 1 до 10 секунд (05-3).

## П

- **Песочница пода** (pod sandbox) — пустой контейнер pause, который держит network namespace, пока живёт под (01-2).
- **Песочница рантайма** (runtime sandbox) — отдельное ядро или ВМ между контейнером и узлом, например gVisor или Kata (06-2).
- **Плагин kubectl** (plugin) — программа kubectl-имя в PATH, которую kubectl запускает как kubectl имя (00-2).
- **Плоскость данных** (data plane) — то, что исполняет решения: контейнеры, сеть, правила пересылки, прокси (01-1).
- **Плоскость управления** (control plane) — узлы и компоненты, которые принимают решения: API-сервер, etcd, scheduler, controller-manager (00-1).
- **Под** (Pod) — наименьшая единица, которую создаёт и планирует Kubernetes: контейнеры на одном узле с общими сетью и томами (01-1).
- **Подпись образа** (image signature) — криптографическое утверждение «этот дайджест выпустили мы» (06-4).
- **Подресурс** (subresource) — отдельная точка API у объекта, например /status, /scale, /eviction (00-2).
- **Подсказка очереди** (QueueingHint) — ответ плагина scheduler, помогает ли событие вернуть под в активную очередь (05-3).
- **Политика аудита** (audit policy) — файл с видом Policy, который задаёт уровень записи для каждого запроса (06-4).
- **Политика синхронизации** (sync policy) — поле syncPolicy в Application: кто запускает sync и что делать с лишним (08-1).
- **Пользовательский ресурс** (custom resource, CR) — экземпляр типа, который добавлен в API через CRD (09-1).
- **Порог выселения** (threshold) — значение сигнала узла, при котором kubelet начинает выселять поды (05-5).
- **Порядковый номер** (ordinal) — число от 0 до N−1 в имени пода StatefulSet (02-3).
- **Привязка PVC** (binding) — связь «один PVC — один PV», которую создаёт контроллер (04-2).
- **Принятые ресурсы** (allocated) — значение, которое kubelet подтвердил и учёл в расчёте узла при resize на месте (05-2).
- **Приоритет** (priority) — число в PriorityClass, по которому scheduler решает, чей под важнее (02-4).
- **Проба** (probe) — периодическая проверка контейнера, которую делает kubelet: startup, liveness, readiness (02-1).
- **Провайдер Gateway API** (platform provider) — тот, кто поставляет реализацию Gateway API и описывает её тип (03-4).
- **Прокси смешанных версий** (mixed version proxy) — функция API-сервера, которая пересылает запрос соседу нужной версии при обновлении (10-3).
- **Промоушен** (promotion) — перенос проверенной версии из одного окружения в другое (08-2).
- **Пространство имён** (namespace) — логическая область имён внутри кластера и единица политик (01-1).
- **Пространство имён ядра** (Linux namespace) — механизм ядра, который даёт процессам собственный вид ресурса: сеть, PID, IPC, монтирования (01-2).
- **Пул узлов** (node pool) — группа одинаковых узлов, которую облако обновляет и масштабирует вместе (10-3).

## Р

- **Радиус поражения** (blast radius) — всё, что перестаёт работать при отказе одного компонента (11-4).
- **Разрешение на ссылку** (ReferenceGrant) — объект в namespace цели, который разрешает ссылку из другого namespace (03-4).
- **Расхождение версий** (version skew) — допустимое расхождение версий компонентов кластера (00-1).
- **Ревизия etcd** (revision) — глобальный счётчик изменений etcd; каждая запись увеличивает его на единицу (01-1).
- **Ревизия релиза** (release revision) — номер версии релиза Helm: каждое изменение создаёт новую (07-1).
- **Режим доступа** (access mode) — заявка на то, как том можно монтировать: RWO, ROX, RWX, RWOP (04-2).
- **Релиз** (release) — установленный в кластер экземпляр чарта с именем и namespace (07-1).
- **Реплика** (replica) — вторая копия базы, которая повторяет все изменения первой (04-3).
- **Ротация сертификата** (rotation) — замена сертификата новым до истечения старого без участия человека (10-4).

## С

- **Сборщик метрик** (scraper) — внешняя программа вроде Prometheus, которая по расписанию забирает метрики (11-1).
- **Сборщик мусора** (garbage collector) — часть kube-controller-manager, которая удаляет объекты, чей владелец исчез (01-3).
- **Сверка** (reconciliation) — повторяющийся цикл, который контроллер Argo CD проходит для каждого Application (08-1).
- **Селектор** (selector) — условие на метки объектов (01-3).
- **Селектор по полям** (field selector) — условие на поля объекта, например status.phase=Running (01-3).
- **Сертификат** (certificate) — подписанный центром сертификации документ, который связывает имя хоста с открытым ключом (03-5).
- **Сигнал** (signal) — уведомление ядра процессу: SIGTERM просит завершиться, SIGKILL убивает (02-1).
- **Сигналы выселения** (eviction signals) — измеряемые значения ресурсов узла, которые kubelet сверяет с порогами (05-5).
- **Слой агрегации** (aggregation layer) — механизм, через который API-сервер передаёт запросы расширениям API (10-1).
- **Событие** (event) — запись компонента о том, что он делал с объектом: Scheduled, Pulling, Failed, BackOff (02-1).
- **Событие аудита** (audit event) — одна JSON-строка в логе аудита об одном запросе на одной стадии (06-4).
- **Состояние контейнера** (container state) — одно из трёх состояний в status.containerStatuses: Waiting, Running, Terminated (02-1).
- **Срок etcd** (term) — номер эпохи выборов в etcd; растёт на единицу при каждых выборах (10-2).
- **Стадия аудита** (stage) — момент жизни запроса, на котором API-сервер пишет событие (06-4).
- **Статический под** (static pod) — под из файла на узле, который kubelet запускает сам, без API-сервера (00-2).
- **Статус узла** (node.status) — объект с условиями (Ready, MemoryPressure…), ресурсами и списком образов узла (01-2).
- **Стратегия обновления** (strategy) — правило, по которому Deployment переводит реплики на новый ReplicaSet (02-2).
- **Субчарт** (subchart) — чарт-зависимость в каталоге charts/ родителя (07-2).
- **Субъект** (subject) — результат аутентификации: имя, список групп и дополнительные поля (06-1).

## Т

- **Тег образа** (tag) — читаемое имя версии образа, например 2.1; в отличие от дайджеста может указывать на другой образ (02-2).
- **Терпимость** (toleration) — запись в поде, которая позволяет терпеть taint узла (01-2).
- **Том** (volume) — каталог, который монтируют в один или несколько контейнеров пода (02-1).
- **Том из образа** (image volume) — том, который монтирует файлы образа в под только для чтения (04-2).
- **Топологическое распределение** (topology spread) — равномерное распределение подов по доменам с ограничением maxSkew (05-3).
- **Троттлинг** (throttling) — принудительная пауза процессов контейнера, когда они выбрали квоту cpu.max (05-1).

## У

- **Узел** (node) — машина, на которой kubelet запускает поды (00-1).
- **Уровень PSS** (level) — один из трёх наборов требований Pod Security Standards: privileged, baseline, restricted (06-3).
- **Уровень аудита** (level) — сколько данных о запросе попадает в событие аудита (06-4).
- **Условие** (condition) — запись в status со статусом True или False и временем изменения (02-1).

## Ф

- **Фаза пода** (phase) — грубая сводка о положении пода в status.phase; всего пять фаз (02-1).
- **Финализатор** (finalizer) — строка в metadata.finalizers: пока список непуст, API-сервер не удаляет объект (01-3).
- **Функциональный гейт** (feature gate) — флаг компонентов кластера, который включает или выключает функцию (02-3).

## Х

- **Хук Argo CD** (hook) — объект, который Argo CD запускает на фазе sync: PreSync, Sync, PostSync или SyncFail (08-1).
- **Хук Helm** (hook) — объект чарта с аннотацией helm.sh/hook, который Helm создаёт в нужный момент жизни релиза (07-1).
- **Хук preStop** (preStop hook) — действие, которое kubelet выполняет перед SIGTERM: exec, httpGet или sleep (02-5).

## Ц

- **Цикл планирования** (scheduling cycle) — этап scheduler, на котором выбирается узел; циклы разных подов идут по очереди (05-3).
- **Цикл привязки** (binding cycle) — этап scheduler, на котором выбор записывается в кластер; такие циклы идут параллельно (05-3).
- **Цикл согласования** (reconcile loop) — бесконечный цикл контроллера: сравнить желаемое с фактическим и устранить разницу (01-1).

## Ч

- **Чарт** (chart) — пакет Helm: каталог с шаблонами манифестов и значениями по умолчанию (07-1).

## Ш

- **Шаблон пода** (pod template) — раздел spec.template Deployment: образ, переменные, ресурсы, метки, пробы (02-2).
- **Шлюз планирования** (scheduling gate) — строка в spec.schedulingGates; пока она есть, scheduler не рассматривает под (05-3).

## Э

- **Эндпоинт** (endpoint) — адрес пода и порт, на которые Service отправляет трафик (03-2).
- **Эфемерное хранилище** (ephemeral storage) — локальный диск узла, который под использует временно: слой записи, логи, emptyDir (05-2).
- **Эфемерный контейнер** (ephemeral container) — временный контейнер с инструментами, который добавляют в работающий под для отладки (00-2).

## A (латиница)

- **ACME** (Automatic Certificate Management Environment) — протокол автоматического выпуска сертификатов, например в Let's Encrypt (03-5).
- **Active queue** — очередь scheduler с подами, готовыми к попытке (05-3).
- **Admission** — этапы после авторизации: изменяющий допуск, проверка схемы, проверяющий допуск (01-1).
- **API Priority and Fairness** (APF) — защита API-сервера: запросы делятся на очереди по приоритетам, шумным клиентам отвечает 429 (01-1).
- **API-сервер** (API server, kube-apiserver) — единственная точка входа в кластер: через него идут все чтения и изменения объектов (00-2).
- **APIService** — запись, которая регистрирует группу агрегированного API, например metrics.k8s.io (09-2).
- **AppArmor** — LSM, который описывает доступ программы профилем по пути; входит в Ubuntu (06-2).
- **Application** — объект Argo CD, который связывает источник в Git с местом в кластере (08-1).
- **ApplicationSet** — объект Argo CD из шаблона Application и генератора параметров (08-2).
- **Argo CD** — GitOps-агент: берёт манифесты из Git, сравнивает с кластером и применяет (08-1).
- **ARP** (Address Resolution Protocol) — протокол, который по IP находит MAC-адрес соседа в том же сегменте (03-1).

## B (латиница)

- **BestEffort** — класс QoS пода без requests и limits; его выселяют первым (05-1).
- **Blue-green** — обновление узлов созданием нового пула, переносом нагрузки и удалением старого (10-3).
- **Break-glass** — аварийная учётная запись на случай, когда обычный доступ сломан (10-4).
- **Burstable** — класс QoS пода, у которого requests меньше limits или заданы не у всех (05-1).

## C (латиница)

- **cainjector** — компонент cert-manager, который подставляет caBundle в конфигурацию вебхука (09-2).
- **CEL** (Common Expression Language) — язык выражений для политик допуска и фильтров устройств в DRA (05-3).
- **cert-manager** — контроллер, который выпускает и продлевает сертификаты как объекты Kubernetes (03-5).
- **cgroup** (control group) — механизм ядра, который объединяет процессы в группу и ограничивает её ресурсы (01-2).
- **cgroup v2** (unified hierarchy) — вторая версия cgroup, где все контроллеры собраны в одно дерево; обязательна с 1.35 (01-2).
- **Challenge** — проверка ACME, что заказчик владеет именем (03-5).
- **Cluster Autoscaler** (CA) — программа, которая добавляет и убирает узлы в готовых группах узлов (05-4).
- **ClusterIP** — тип Service по умолчанию: виртуальный адрес только внутри кластера (03-2).
- **ClusterIssuer** — issuer cert-manager на весь кластер (03-5).
- **ClusterNetworkPolicy** — кластерная сетевая политика в network-policy-api, замена AdminNetworkPolicy (03-6).
- **ClusterRole** — набор правил RBAC на весь кластер (06-1).
- **ClusterRoleBinding** — выдача ClusterRole субъектам во всём кластере (06-1).
- **CNI** (Container Network Interface) — стандарт, по которому рантайм вызывает сетевой плагин (01-2).
- **CNI-агент** (CNI agent) — DaemonSet сети (kindnet, Calico, Cilium): раздаёт подсети, строит маршруты, применяет NetworkPolicy (01-2).
- **Condition CRD** (Condition) — стандартная запись состояния в status пользовательского ресурса (09-1).
- **ConfigMap** — объект с обычными настройками: пары ключ-значение или целые файлы (04-1).
- **conntrack** (connection tracking) — подсистема ядра, которая ведёт таблицу проходящих соединений (03-1).
- **containerd** — контейнерный рантайм стенда; работает как служба systemd (01-2).
- **Controller revision** (ControllerRevision) — снимок версии шаблона StatefulSet, на который указывает метка controller-revision-hash (02-3).
- **Cordon** — пометка узла как неподходящего для новых подов; существующие остаются (05-5).
- **CRD** (CustomResourceDefinition) — объект, который регистрирует в API-сервере новый тип (01-3).
- **CRI** (Container Runtime Interface) — интерфейс, которым kubelet управляет контейнерным рантаймом (00-2).
- **CronJob** — контроллер, который создаёт Job по расписанию (02-4).
- **CSI** (Container Storage Interface) — стандартный интерфейс между Kubernetes и хранилищем (04-2).
- **CSR** (CertificateSigningRequest) — API-объект с публичным ключом и просьбой выдать сертификат (06-1).

## D (латиница)

- **DaemonSet** — контроллер, который держит один под на каждом подходящем узле (01-2).
- **Default deny** — NetworkPolicy, которая выбирает все поды и закрывает направление целиком (03-6).
- **DEK** (data encryption key) — ключ данных, которым шифруют объекты в конвертном шифровании (04-1).
- **Deployment** — контроллер, который хранит желаемую версию и число копий и сам приводит к ним кластер (02-2).
- **Discovery** — запрос к API-серверу за списком доступных типов объектов и их путей (00-2).
- **DNAT** (destination NAT) — подмена адреса назначения, например ClusterIP на IP пода (03-2).
- **DNS** (Domain Name System) — служба, которая превращает имя в IP-адрес (03-3).
- **Downward API** — механизм, которым под узнаёт о себе через переменные или файлы без запросов к API (02-1).
- **DRA** (Dynamic Resource Allocation) — динамическое выделение устройств, например GPU, через заявки и классы (05-3).
- **Drain** — cordon плюс выселение всех подов узла через Eviction API (05-5).
- **Draining** — статус эндпоинта в Envoy: вывод из работы, новые запросы не идут (11-3).
- **Dry-run** — выполнение команды без сохранения результата: клиентское или серверное (00-2).

## E (латиница)

- **Election timeout** — время без вестей от лидера etcd (1000 мс по умолчанию), после которого начинаются выборы (10-2).
- **emptyDir** — пустой каталог на диске узла или в памяти; живёт, пока под на узле (02-1).
- **EncryptionConfiguration** — файл с правилами шифрования Secret в etcd, флаг --encryption-provider-config (04-1).
- **EndpointSlice** — объект API с частью списка эндпоинтов Service и их условиями (03-2).
- **Envelope encryption** — конвертное шифрование: данные шифрует DEK, а DEK шифрует KEK в KMS (04-1).
- **Envoy** — прокси, на котором работает Envoy Gateway; плоскость данных Gateway API (03-4).
- **escalate и bind** (escalate, bind) — глаголы RBAC «менять роль» и «привязывать роль»; их выдача равна выдаче всех прав кластера (06-1).
- **etcd** — key-value хранилище всего состояния кластера с репликацией по Raft (01-1).
- **Eviction** — см. «Выселение»; не путать с preemption («Вытеснение») (05-5).

## F (латиница)

- **Fail open** — пропуск при отказе: если агент не работает, пакеты проходят без политик (03-6).
- **FlowSchema** — объект APF: кому какой приоритет (01-1).
- **FQDN** (fully qualified domain name) — полное имя с точкой в конце; резолвер не добавляет к нему search-домены (03-3).

## G (латиница)

- **Garbage collector images** (image GC) — удаление kubelet'ом неиспользуемых образов по порогам диска (01-2).
- **Gateway** — экземпляр входа в Gateway API: описывает listeners, создаётся оператором кластера (03-4).
- **Gateway API** — типизированный API входа: GatewayClass, Gateway, HTTPRoute (03-4).
- **GatewayClass** — тип входа на весь кластер, который называет контроллер в controllerName (03-4).
- **generateName** — префикс имени, к которому сервер добавляет случайный суффикс (01-3).
- **Guaranteed** — класс QoS, у которого requests равны limits для CPU и памяти (05-1).
- **gVisor** — песочница рантайма (обработчик runsc): исполняет системные вызовы в собственном ядре в пользовательском пространстве (06-2).

## H (латиница)

- **HA** (high availability) — высокая доступность; control plane из трёх или пяти узлов (10-1).
- **Headless Service** (Headless) — Service с clusterIP: None; DNS отдаёт адреса подов напрямую (00-1).
- **Heartbeat** — сигнал лидера etcd последователям каждые 100 мс (10-2).
- **Hook** — см. «Хук Argo CD» (08-1) и «Хук Helm» (07-1) (08-1).
- **HPA** (Horizontal Pod Autoscaler) — встроенный контроллер, который меняет число реплик по метрикам (05-4).
- **HSTS** (HTTP Strict Transport Security) — заголовок, который велит браузеру ходить на имя только по HTTPS (03-5).
- **HTTPRoute** — набор правил, который выбирает бэкенд по хосту, пути и заголовкам (03-4).

## I (латиница)

- **immutable** — поле ConfigMap и Secret, которое запрещает любые правки data после создания (04-1).
- **Ingress** — первый API входа: хост, путь и TLS; остальное через аннотации контроллера (03-4).
- **IngressClass** — объект, который связывает Ingress с контроллером (03-5).
- **Init-контейнер** (init container) — контейнер из initContainers, который выполняется до основных и должен завершиться с кодом 0 (02-1).
- **inotify** — механизм ядра Linux, который сообщает программам об изменениях файлов (00-1).
- **IPAM** (IP address management) — выдача адресов подам из подсети узла (01-2).
- **IPC** (inter-process communication) — межпроцессное взаимодействие; пространство имён IPC у пода общее (02-1).
- **Issuer** — issuer cert-manager в одном namespace: ACME-сервер, собственный CA, Vault (03-5).

## J (латиница)

- **Job** — контроллер, который запускает под до успешного завершения (01-2).
- **JWT** (JSON Web Token) — строка из заголовка, claims и подписи; так выглядит токен ServiceAccount (06-1).

## K (латиница)

- **Karpenter** — программа, которая сама подбирает и создаёт узлы под поды и убирает лишние (05-4).
- **KEDA** (Kubernetes Event-driven Autoscaling) — надстройка над HPA с сигналами из очередей, расписаний и внешних систем (05-4).
- **KEK** (key encryption key) — главный ключ, который хранится в KMS и шифрует DEK (04-1).
- **kind** (Kubernetes in Docker) — инструмент, который запускает узлы Kubernetes как контейнеры Docker (00-1).
- **KMS** (Key Management Service) — внешняя служба, которая хранит главный ключ и шифрует (04-1).
- **kube-controller-manager** — процесс, в котором работает около 40 контроллеров (01-1).
- **kube-proxy** — агент на узле, который пишет правила iptables, nftables или ipvs для Service (01-1).
- **kube-scheduler** — компонент, который выбирает узел для каждого пода без узла (01-1).
- **kube-state-metrics** (KSM) — программа, которая превращает поля объектов API в метрики (11-1).
- **kubeadm** — утилита, которая создаёт и обновляет кластер на подготовленных узлах (10-1).
- **kubelet** — агент на узле: запускает контейнеры назначенных подов и отправляет их status (00-2).
- **kubent** (kube-no-trouble) — инструмент поиска устаревших версий API в живом кластере (10-3).
- **kuberc** (kubectl preferences) — файл личных настроек kubectl, отдельный от kubeconfig, с 1.34 (00-2).
- **kured** (Kubernetes Reboot Daemon) — перезагружает узлы по одному после обновления пакетов и сам делает drain (10-4).

## L (латиница)

- **Lease** — запись с именем держателя и временем последнего продления; основа выбора лидера (01-1).
- **Limit** — потолок ресурса, который держит ядро (05-1).
- **LimitRange** — объект namespace, который задаёт значения по умолчанию и пределы requests и limits (05-2).
- **Listener** — пара «порт и протокол» Gateway, иногда с именем хоста (03-4).
- **Liveness probe** (livenessProbe) — проба живости: не завис ли процесс; провал ведёт к рестарту (02-5).
- **LoadBalancer** — тип Service: NodePort плюс внешний балансировщик от облака или MetalLB (03-2).
- **LSM** (Linux Security Module) — модуль безопасности ядра: AppArmor или SELinux (06-2).

## M (латиница)

- **Memory Manager** — компонент kubelet, который привязывает память Guaranteed-подов к NUMA-узлам (05-1).
- **Mirror pod** — запись в API, по которой видно static pod (01-1).
- **MTU** (maximum transmission unit) — максимальный размер пакета без фрагментации (03-1).
- **Mutating admission** — этап допуска, на котором плагины и вебхуки дописывают значения в объект (01-1).
- **MutatingAdmissionPolicy** (MAP) — политика на CEL, которая возвращает патч объекта и работает внутри API-сервера (06-3).
- **MVCC** (multi-version concurrency control) — etcd при изменении ключа пишет новую версию, а старую оставляет до компакции (10-2).

## N (латиница)

- **NAT** (network address translation) — подмена адреса в заголовке пакета (03-1).
- **NetworkPolicy** — объект, который перечисляет разрешённые соединения для выбранных подов (03-6).
- **Node-pressure eviction** — см. «Вытеснение по давлению» (05-5).
- **NodePool** — объект Karpenter с ограничениями узлов и политикой уборки (05-4).
- **NodePort** — тип Service: ClusterIP плюс порт 30000–32767 на каждом узле (03-2).

## O (латиница)

- **OCI** — стандарт формата образа и запуска контейнера (Open Container Initiative) (01-2).
- **OIDC** (OpenID Connect) — стандарт, по которому внешний провайдер выдаёт подписанный JWT (06-1).
- **Overcommit** — сумма limits на узле больше его памяти (05-1).
- **Overhead** — ресурсы, которые тратит сама песочница пода, например ВМ Kata (05-2).

## P (латиница)

- **Page cache** — кэш страниц: файлы, которые контейнер читал и писал (05-1).
- **Pause** — контейнер песочницы пода, который держит network namespace (01-2).
- **PersistentVolume** (PV) — конкретный том; объект уровня кластера без namespace (01-1).
- **PersistentVolumeClaim** (PVC) — заявка пода на том: размер, режим доступа, класс (00-1).
- **PITR** (point-in-time recovery) — восстановление базы на момент времени из базовой копии и архива WAL (04-3).
- **PKI** (public key infrastructure) — набор центров сертификации, ключей и сертификатов (10-1).
- **PLEG** (Pod Lifecycle Event Generator) — часть kubelet, которая раз в секунду сверяет состояние контейнеров с рантаймом (01-2).
- **Pod affinity** — привязка пода к узлам, где уже есть нужные поды (05-3).
- **Pod anti-affinity** — отталкивание пода от узлов, где есть указанные поды (05-3).
- **Pod sandbox** — см. «Песочница пода» (01-2); не путать с «Песочница рантайма» (06-2) (01-2).
- **Pod Security Admission** (PSA) — встроенный плагин PodSecurity, который применяет уровни PSS по меткам namespace (06-3).
- **Pod Security Standards** (PSS) — три фиксированных набора требований к полям пода: privileged, baseline, restricted (06-3).
- **PodDisruptionBudget** (PDB) — см. «Бюджет прерываний» (05-5).
- **podFailurePolicy** — правила Job, которые реагируют на код выхода контейнера или условие пода (02-4).
- **Preemption** — см. «Вытеснение»; не путать с eviction («Выселение») (05-3).
- **PriorityClass** — объект кластера с числом приоритета (05-3).
- **Projected volume** — том из нескольких источников: ConfigMap, Secret, Downward API, токен (04-1).
- **provisioner** — программа, которая умеет создавать тома в конкретном хранилище (04-2).
- **Prune** — удаление Argo CD объектов, которые когда-то применил, а в Git их больше нет (08-1).
- **PSI** (Pressure Stall Information) — счётчики ядра, показывающие долю времени ожидания ресурса (05-1).
- **Pull-модель** (pull) — агент внутри кластера сам забирает манифесты из Git (08-1).
- **Push-модель** (push) — CI после сборки применяет манифесты командой kubectl apply (08-1).

## R (латиница)

- **Raft** — алгоритм согласования реплик через выбор лидера, на котором работает etcd (01-1).
- **RBAC** (role-based access control) — доступ по ролям: Role, ClusterRole, RoleBinding, ClusterRoleBinding (06-1).
- **Readiness gates** — внешние условия, которые входят в готовность пода (02-5).
- **Readiness probe** (readinessProbe) — проба готовности: можно ли слать трафик (02-5).
- **ReplicaSet** — объект, который держит заданное число одинаковых подов (01-1).
- **Request** — сколько ресурса просит под: по нему scheduler выбирает узел (05-1).
- **Resize на месте** (in-place resize) — изменение CPU и памяти работающего контейнера без пересоздания пода (05-2).
- **Reverse proxy** — процесс, который принимает запросы клиентов и пересылает их на бэкенды (03-4).
- **Role** — набор правил RBAC внутри одного namespace (06-1).
- **RoleBinding** — выдача Role или ClusterRole субъектам в одном namespace (06-1).
- **RPO** (Recovery Point Objective) — сколько данных можно потерять: от последней точки восстановления до аварии (04-3).
- **RTO** (Recovery Time Objective) — сколько сервис может лежать: от аварии до рабочего состояния (04-3).
- **Runtime sandbox** — см. «Песочница рантайма» (06-2); не путать с «Песочница пода» (01-2) (06-2).
- **RuntimeClass** — объект кластера, который выбирает обработчик рантайма для пода (05-2).

## S (латиница)

- **SAN** (subject alternative name) — список адресов и имён внутри сертификата (10-1).
- **SBOM** (Software Bill of Materials) — список компонентов образа; прикладывается как подписанное свидетельство (06-4).
- **Scaler** — готовый модуль KEDA для источника сигнала: cron, Prometheus, Kafka (05-4).
- **Scheduler** — см. «kube-scheduler» (01-1).
- **seccomp** (secure computing mode) — фильтр, который ограничивает системные вызовы процесса (06-2).
- **Secret** — объект для секретных данных; data хранит base64, а не шифрование (03-5).
- **Self-heal** — возврат кластера к состоянию Git при ручной правке (08-1).
- **SelfSubjectReview** — запрос «каким меня видит кластер»; GA в 1.28, команда kubectl auth whoami (06-1).
- **SELinux** — подсистема ядра, которая помечает файлы и процессы метками безопасности (04-2).
- **Server-side apply** (SSA) — режим kubectl apply --server-side: объекты сливает сервер по менеджерам полей (01-3).
- **Service** — объект с постоянным виртуальным адресом и DNS-именем для группы подов (03-2).
- **ServiceAccount** (ServiceAccount, SA) — учётная запись службы: идентичность процессов в подах, единственный субъект с объектом в API (06-1).
- **Sidecar** (sidecar container) — вспомогательный контейнер рядом с основным; нативно — init с restartPolicy: Always (02-1).
- **Skew** — разница числа подов в домене и в домене с наименьшим числом (05-3).
- **SNAT** (source NAT) — подмена адреса отправителя; masquerade берёт адрес исходящего интерфейса (03-1).
- **SNI** (Server Name Indication) — имя сервера в первом сообщении TLS, открытым текстом (03-5).
- **SOPS** (Secrets OPerationS) — шифрует значения в YAML и оставляет ключи видимыми (08-2).
- **Startup probe** (startupProbe) — проба запуска: закончился ли старт (02-5).
- **StatefulSet** — контроллер подов со стабильными именем, адресом и томом (02-3).
- **StorageClass** — рецепт создания PV: драйвер, параметры, политика удаления, режим привязки (04-2).
- **StorageVersionMigration** — ресурс, который перезаписывает объекты CRD в новой версии хранения (09-1).
- **stringData** — поле Secret только для записи: значения открытым текстом, API кодирует их в base64 (04-1).
- **Surge** — временные дополнительные узлы на время обновления пула (10-3).
- **Swap** — область диска для редко используемых страниц памяти; по умолчанию NoSwap (05-2).
- **Sync wave** — см. «Волна синхронизации» (08-1).

## T (латиница)

- **Taint** — метка-запрет на узле: новые поды не попадут, текущие уйдут, если не терпят её (01-2).
- **Termination message** — сообщение о причине завершения контейнера в status (02-1).
- **Throttling** — см. «Троттлинг» (05-1).
- **TLS** (Transport Layer Security) — протокол шифрования соединения (03-5).
- **TLS bootstrap** — выдача kubelet'у сертификата по временному токену без участия человека (10-1).
- **Topology spread** — см. «Топологическое распределение» (05-3).
- **transition rule** — правило CRD с oldSelf, которое срабатывает только при обновлении (09-1).
- **TTL** (time to live) — срок жизни записи в кэше DNS (03-3).

## U (латиница)

- **Unschedulable pods** — список scheduler: поды, для которых нет узла и которые ждут события (05-3).

## V (латиница)

- **Validating admission** — этап допуска, на котором плагины и политики только разрешают или отклоняют (01-1).
- **ValidatingAdmissionPolicy** (VAP) — правило проверки на CEL, которое выполняется внутри API-сервера (06-3).
- **Validation ratcheting** — правило GA 1.33: обновление не отклоняют из-за полей, которые оно не меняет (09-1).
- **Velero** — копирует объекты Kubernetes и данные томов в объектное хранилище (04-3).
- **veth** (veth pair) — пара соединённых виртуальных интерфейсов: что вошло в один, выходит из другого (03-1).
- **VolumeGroupSnapshot** — согласованный снимок нескольких PVC, GA в 1.36 (04-2).
- **VolumeSnapshot** — копия тома на уровне хранилища (04-2).
- **VPA** (Vertical Pod Autoscaler) — проект, который подбирает requests и limits пода по истории потребления (05-4).

## W (латиница)

- **WAL** (write-ahead log) — журнал, в который база сначала записывает каждое изменение (04-3).
- **Watch** — подписка клиента на поток изменений объектов с resourceVersion (01-1).
- **Working set** — рабочий набор памяти: использование минус неактивный файловый кэш (05-1).

## X (латиница)

- **xDS** — набор API, по которым прокси Envoy получает конфигурацию (03-4).
